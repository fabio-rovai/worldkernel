# Roadmap

Built in public: every milestone is tracked as a GitHub issue, every claim lands with a test, and negative results get written up rather than buried. Figures and numbers in the README are regenerated by the scripts in `experiments/` and locked in by `tests/`.

## v0.1: the kernel exists (done, this release)

- [x] `CouplingKernel`: the PSD second-moment matrix over potential worlds
- [x] `TwoWorldKernel` and the canonical witness pair (PN 0.286 vs 0.500, identical rungs 1-2)
- [x] Mediation NDE identified interval via the 64-atom response-type LP (spans zero)
- [x] Nested bounds: Fréchet ⊇ PSD ⊇ exact, with the SDP alive at k = 40
- [x] Sly-Sun barrier instruments: order parameter, d_c = 5.141, BP vs exact marginals
- [x] Tests, CI, reproduction scripts

## v0.1.x increments (done, built in public)

- [x] Real public trials: NSW, IST, STAR through the kernel; sampling vs identification decomposition (IST: 7.6x)
- [x] The barrier, constructively (pulled forward from v0.5 scope): Weitz certified marginal intervals (`weitz_interval`), and exact transfer-matrix computation on bounded-width, above-critical-degree worlds (`ring_of_cliques`, `transfer_marginals`)
- [x] Ontology-to-width bridge (from v0.5 scope): `min_fill_order` width certificates, general variable-elimination exact marginals (`treewidth_marginal`), `disjointness_graph` taxonomy worlds; width tracks branching, not size (1,110 classes, degree 13, exact in 1.3 s)
- [x] The MCP server (from v0.4 scope): `worldkernel-mcp` exposes 8 kernel tools (counterfactual bounds, NDE from measured records, certified and exact marginals, barrier diagnostics) to any MCP client; `nde_interval_from_record` agent-facing entry point

## v0.2: estimation (the kernel meets data)

- [ ] Finite-sample diagonals: estimate marginals from trial data with confidence intervals, propagate into the bounds
- [ ] Balke-Pearl instrumental-variable LP as the primary classical baseline, same API
- [ ] The 2-mediator, 4096-atom LP: report interval and timing (the barrier made empirical)
- [ ] Off-the-shelf comparison: DoWhy/PyWhy bounds on the same instances

## v0.3: coupling discovery

- [ ] Can a search procedure (GA or gradient-free) plus an LLM teacher discover the *assumption* that pins rung 3 (monotonicity, cross-world independence), which the LLM alone does not surface?
- [ ] Assumption language: a small vocabulary of couplings (monotone, independent, bounded-correlation, ontology-shaped) with admissibility checks
- [ ] Report: which assumptions are discoverable from which data regimes

## v0.4: the agent loop

- [ ] Kernel as the world model of an acting agent: LLM proposes structure (frontier sensor), kernel computes rung 3 and certifies bounds
- [ ] Decision-making under non-identification: act on the interval, not a point
- [ ] Interface for external orchestrators (MCP server exposing kernel queries as tools)

## v0.5: structure at scale

- [ ] Ontology-shaped couplings: use class structure to restrict the response-type polytope below the counting barrier
- [ ] SDP relaxations beyond pairwise (third-order moments, Lasserre level 2)
- [ ] Benchmark battery: the 300-SCM rigid-test suite, public leaderboard

## Principles

1. The kernel is the intelligence; any LLM in the loop is a sensor, never the calculator.
2. Non-identification is surfaced, never hidden: intervals over points.
3. Restriction is a design constraint, not a concession: stay below the barrier by structure.
4. Every number in a claim is reproducible by a script in this repo and locked by a test.
